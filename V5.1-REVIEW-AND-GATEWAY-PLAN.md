# CEOAI V5.1 — repository review and safe integration plan

Status: review prepared against the existing `main` (V4.9) and `v5.0` branch. This document does not change the production Worker, Cloudflare settings, secrets, or deployment.

## Repository state verified

- `main` uses `ceoai-index-v4.9.mjs`, `test-ceoai-v4.9.mjs`, and package version 4.9.0.
- Existing branch `v5.0` uses `ceoai-index-v5.0.mjs`, `test-ceoai-v5.0.mjs`, and package version 5.0.0.
- V5.0 includes capability-aware AI routing, several OpenAI-compatible adapters, quota cooldowns, and search enrichment.
- V5.0 `wrangler.toml` still has `workers_dev = true`; its main entry points to V5.0. Do not deploy or change the production branch as part of this review.
- The repository's V5.0 test suite contains the V4.9 regression tests plus additional V5.0 tests. Test execution was not available through the GitHub file-inspection operation, so no claim is made that tests passed in this review.
- The current `README.md` points to `README-CEOAI-V5.0.txt`; preserve that documentation until the source and test changes are implemented and verified.

## Confirmed implementation risks to address before production

1. **History limit can stop a session.** The chat handler can return 503 when history exceeds `MAX_HISTORY_MESSAGES` and compression does not succeed. Retain a bounded, valid suffix of history rather than permanently blocking a session; preserve a final user message and never silently lose the current prompt.
2. **Rate-limit messaging is inconsistent.** The configured native limiter is 20 requests per 60 seconds, while the public error says 20 per hour and `Retry-After` uses 3600 seconds. Align the text and retry header with the actual binding. Keep any KV fallback clearly separate because KV read-modify-write is not atomic.
3. **Provider request deadline is too long when failover loops.** The per-provider timeout is 25 seconds, while the browser aborts after 30 seconds. Add one total deadline for the whole provider loop and pass the remaining time into every outbound request. Leave enough time for the Worker to return a controlled response.
4. **Gemini key is in the URL query string.** Move it to the `x-goog-api-key` header so the key is less likely to enter URL logs. Make the Gemini model an environment-configured value and verify its availability before enabling it.
5. **Provider model IDs must be verified.** V5.0 documentation and code contain model defaults that may have changed or been retired. Do not replace them with guessed IDs: use a configured model ID, validate format, and verify it against the provider's current model list before enabling that provider.
6. **Cooldowns need classification and bounded retry hints.** Capture `Retry-After`, distinguish burst throttling from exhausted quota where the provider response supports it, pause invalid credentials/models briefly, and do not return provider error bodies or secrets to clients. Avoid assuming every 429 means a daily quota reset.
7. **Conversation summary is untrusted content.** Label the stored summary as untrusted historical data in the system context. The summarizer prompt must treat all conversation text as data and must not follow instructions contained in it. Bound the summarizer timeout.
8. **Session creation can consume KV writes.** The root page currently creates a KV session key for a visitor without a valid session cookie. Add an appropriate rate limit or move to a signed, short-lived session token before public high-traffic use.
9. **Memory deletion is missing from the UI/API.** Add an authenticated, same-origin `POST /api/reset` endpoint that deletes only the current session's memory and a “Nova sesija” control that clears the visible chat. Return success only after KV deletion succeeds.
10. **Free-only policy must be enforced in code.** DeepSeek, xAI, NVIDIA, Mistral, Hugging Face, search APIs, and aggregators must not be described as free merely because a key exists. Keep risky providers disabled by default; enable only with a confirmed no-billing/free-tier setting. OpenRouter models must be explicitly verified and satisfy the `:free` rule.
11. **Cloudflare service binding is not implemented yet.** The V5.0 Worker currently exposes only the chat route in its router; no confirmed `/internal/complete` route or `GATEWAY_SECRET` authentication was found in the inspected entry file. ContentCraft must not call it until the internal route, authentication, rate limiting, and tests exist.
12. **Provider registry proposal is not yet integrated.** The supplied V5.0 registry is a design proposal, not a drop-in patch: its adapter and capability names do not match all current V5.0 names, it lists data providers whose adapters are not implemented, and its reset policy is only a proposal. Reconcile names and behavior before replacing the current pool.

## Safe implementation order

### Phase A — Worker reliability and privacy
- Add regression tests for history overflow, timeout budget, Retry-After consistency, Gemini header auth, untrusted summaries, and reset behavior.
- Fix the Worker and tests together.
- Keep the AI opt-in and provider free-only gates fail-closed.
- Run `npm run verify` on Node 22+ and add a CI workflow if the repository currently lacks one.

### Phase B — shared provider registry
- Use one registry for provider IDs, adapter, model environment variable, required secrets/binding, capability scores, and free-only gate.
- Keep the existing public response shape stable.
- Implement only adapters that have tests; skip unsupported data-provider entries instead of implying they work.
- Add candidate-ranking, disabled-provider, missing-model, exhausted-quota, 401/403/404, and total-deadline tests.

### Phase C — ContentCraft internal gateway
- Add `POST /internal/complete` protected by a strong `GATEWAY_SECRET` and constant-time comparison.
- Reuse the same provider pool without copying provider keys into ContentCraft.
- Validate payload size, roles, message lengths, last-user-message requirement, and allowed tier.
- Apply a separate gateway rate limiter and return sanitized errors only.
- Add the Cloudflare Pages service binding `CEOAI_GATEWAY` and the matching encrypted secret only after code and tests are ready.
- Add mocked integration tests proving unauthorized calls fail, authorized calls route correctly, no key is returned, and fallback respects the total deadline.

## Production safety checklist

- No API keys or tokens in source, logs, URLs, or test fixtures.
- No paid provider is activated by default.
- No Cloudflare production setting, secret, domain, or deployment is changed by this plan.
- Do not point the production Worker at V5.0 until the tests pass and the owner explicitly approves deployment.
- Keep changes on the existing `v5.0` line unless the owner explicitly approves a different branch or PR.

Repository files and configuration were inspected through GitHub. Runtime tests, live provider calls, Cloudflare binding state, and production deployment state were not executed or independently confirmed during this review.
